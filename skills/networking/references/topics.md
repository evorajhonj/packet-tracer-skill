# Networking topic matrix

Use this as a route into a topic, not as a promise that a helper or every Packet Tracer device implements it. Start with the installed Packet Tracer version, exact device model/modules, ports, topology, and required behavior. Packet Tracer models a subset of IOS and simplifies protocols; the Cisco Packet Tracer FAQ lists modeled protocols but explicitly says results should be compared with real equipment. The FAQ is for Packet Tracer 8.2, so check the installed version as well. [Packet Tracer FAQ and protocol list](https://prelogin-authoring.netacad.com/sites/default/files/cisco-packet-tracer-faq.pdf) · [Packet Tracer FAQ/troubleshooting](https://tutorials.ptnetacad.net/help/default/faqTroubleShoot.htm)

Commands below are IOS-family examples. Confirm them with the actual device's `?` and `show version`; don't treat a rejected command as evidence that the concept or feature is absent from all models. Use host-side tools only where the selected Packet Tracer end device provides them. [Packet Tracer end-device tools](https://tutorials.ptnetacad.net/help/default/config_servers.htm)

| Topic | Design choices to settle | Verify with these commands or tools | Support boundary |
|---|---|---|---|
| OSI and TCP/IP | Trace one flow by encapsulation: application data → TCP/UDP → IP → Ethernet/Wi-Fi. Identify the layer that owns the fault before changing config. | `show interfaces`; host `ipconfig`, `arp -a`, `ping`, `tracert`; Simulation Mode event/PDU details. | A PDU walk-through explains the modeled flow; it is not a timing or performance benchmark. [Cisco TCP/IP overview](https://www.cisco.com/c/en/us/support/docs/ip/routing-information-protocol-rip/13769-5.html) |
| Ethernet, ARP, ICMP | Select media/cable and compatible ports; keep one IP subnet per shared L2 segment; know that ARP resolves local IPv4 next hops and ICMP tests reachability/errors. | `show interfaces`; switch `show mac address-table`; router `show ip arp`; `ping`; Simulation Mode ARP/ICMP event list. | Check pin/port roles and link state on the chosen model. A first ping can be lost while ARP resolves. [Cisco TCP/IP overview](https://www.cisco.com/c/en/us/support/docs/ip/routing-information-protocol-rip/13769-5.html) · [Packet Tracer FAQ](https://tutorials.ptnetacad.net/help/default/faqTroubleShoot.htm) |
| IPv4, masks, VLSM | Count hosts including gateway; allocate largest LANs first; avoid network/broadcast addresses and overlapping subnets; choose /30 or another supported transit size intentionally. | `show ip interface brief`; `show ip route`; host `ipconfig /all`; `ping <gateway>`; check network, mask, usable range, and broadcast by hand or with the skill planner. | Address arithmetic does not configure devices or prove routes. Check mask/host support for nonstandard /31 or /32 links. [Cisco TCP/IP overview](https://www.cisco.com/c/en/us/support/docs/ip/routing-information-protocol-rip/13769-5.html) |
| IPv6 | Choose static, SLAAC, DHCPv6, or dual stack; assign a distinct /64 per LAN; plan link-local next hops and default route; account for ICMPv6 neighbor discovery. | `show ipv6 interface brief`; `show ipv6 route`; `show ipv6 neighbors`; host `ipv6config`, `ping`, `tracert`. | Verify SLAAC/DHCPv6, routing, and any extension features on the exact model. [Cisco IPv6 overview](https://www.cisco.com/site/us/en/learn/topics/networking/what-is-ipv6.html) · [Cisco IPv6 routing guide](https://www.cisco.com/c/en/us/td/docs/routers/ios-xe/ip-routing/b-ip-routing.html) |
| Switching: VLAN, trunk, STP, EtherChannel | Define VLAN IDs and access-port membership; decide trunk allowed/native VLANs at both ends; retain loop prevention; bundle only ports with matching speed, duplex, VLAN/trunk, and channel mode. | `show vlan brief`; `show interfaces trunk`; `show interfaces <port> switchport`; `show spanning-tree vlan <id>`; `show etherchannel summary`. | Syntax and supported STP/channel protocols depend on switch family/software. Check both ends and all member ports; don't disable STP to silence a loop. [Cisco VLAN/trunk guide](https://www.cisco.com/c/en/us/td/docs/switches/lan/c9000/lyr2-fwd/vlan/vlan-configuration-guide/configure-vlan-trunks.html) · [Cisco EtherChannel guide](https://www.cisco.com/c/en/us/td/docs/switches/lan/c9000/lyr2-fwd/etherchannel/etherchannel-configuration-guide/m_ethernetchannel.html) · [Cisco STP verification](https://www.cisco.com/c/en/us/td/docs/switches/lan/c9000/lyr2-fwd/stp/stp-configuration-guide/m-stp.html) |
| Inter-VLAN routing | Choose an L3 switch SVI or router-on-a-stick. Every VLAN needs its own subnet and gateway; a router-on-a-stick link needs matching 802.1Q VLAN tags and an operational trunk. | `show vlan brief`; `show interfaces trunk`; `show ip interface brief`; `show ip route connected`; ping each gateway, then a host in another VLAN. | An L2 switch alone does not route between VLANs. Match the router subinterface, VLAN tag, native-VLAN policy, switch trunk, and gateway. PT model/port support varies. [Cisco VLAN guide](https://www.cisco.com/c/en/us/td/docs/switches/lan/c9000/lyr2-fwd/vlan/vlan-configuration-guide/configure-vlan-trunks.html) |
| Gateway redundancy: HSRP, VRRP, GLBP | Decide whether one active gateway with standby (HSRP/VRRP) or gateway load sharing (GLBP) is intended; assign the same virtual IP/group consistently and set priority, preemption, tracking, and authentication only as required. | `show standby brief`; `show vrrp brief`; `show glbp brief`; verify client gateway is the virtual IP and test a controlled failover if the lab calls for it. | These are separate protocols with different syntax. Require exact platform/release support; a configured group or modeled failover is not proof of real recovery time. [Cisco HSRP](https://www.cisco.com/c/en/us/td/docs/routers/ios-xe/network-services/network-services/m_fhp-hsrp-0.html) · [Cisco VRRP](https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/ntw-servs/b-network-services/m_fhp-vrrp-0.html) · [Cisco GLBP](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/ipapp_fhrp/configuration/xe-16-7/fhp-xe-16-7-book/fhp-glbp.html) |
| Static/default routes | Choose next hop or exit interface and document the return route. Use a default route only when one upstream path is intended; a floating backup needs a higher administrative distance. | `show ip route`; `show ip route <destination>`; `ping <next-hop>`; `traceroute <destination>`; repeat from the far side. | The next hop must resolve through an active path. Recursive, policy, tracked, and equal-cost behavior needs model-specific checks. [Cisco static-route guidance](https://www.cisco.com/c/en/us/support/docs/dial-access/floating-static-route/118263-technote-nexthop-00.html) |
| RIP, OSPF, EIGRP | Pick one protocol supported by the lab; specify networks/interfaces, passive LANs, areas or AS/process values, router IDs where required, and authentication if assigned. | RIP: `show ip protocols`, `show ip route`; OSPF: `show ip ospf neighbor`, `show ip route ospf`; EIGRP: `show ip eigrp neighbors`, `show ip route eigrp`. Then test both directions. | A configured process is not proof of adjacency or reachability. Match area, AS, timers/authentication where configured, masks, and enabled interfaces. [Cisco OSPF guide](https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/ip-routing/b-ip-routing/m_iro-cfg-0.html) · [Cisco EIGRP guide](https://www.cisco.com/en/US/docs/ios-xml/ios/iproute_eigrp/configuration/15-0sy/ire-cfg-eigrp.html) · [Cisco RIP guide](https://www.cisco.com/en/US/docs/ios/zz_trash/config_modules/irr_cfg_info_prot_xe.html) |
| BGP basics | Advanced topic: state the exact router models, software/features, ASNs, peer addresses, address families, and routes to exchange. Separate eBGP/iBGP and policy goals. | `show ip bgp summary`; `show ip bgp`; `show ip route bgp`; verify intended prefixes and an end-to-end path. | Require an explicit compatible model and feature set. Do not claim a full BGP or Internet simulation from protocol presence in a Packet Tracer feature list. [Cisco basic BGP guide](https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/ip-routing/b-ip-routing/m_irg-basic-net-0.html) · [Packet Tracer FAQ](https://prelogin-authoring.netacad.com/sites/default/files/cisco-packet-tracer-faq.pdf) |
| DHCP, DNS, HTTP | Decide which host serves leases and options; reserve gateway/server addresses. For DNS, define A/CNAME records and client resolver; for HTTP, enable service and requested page. | Router DHCP: `show ip dhcp pool`, `show ip dhcp binding`; client `ipconfig /all`, `nslookup <name>`, then browser `http://<name-or-address>`. Check the Packet Tracer Server Services tab for service state/records/files. | Test lease, name resolution, and page delivery separately; a ping does not prove DNS or HTTP. Packet Tracer Server services are configured in the GUI. [Cisco DHCP verification](https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/ip-addressing/b-ip-addressing/m_config-dhcp-server-xe.html) · [Packet Tracer server services](https://tutorials.ptnetacad.net/help/default/config_servers.htm) |
| NTP, SNMP, syslog | Choose a reachable time/log/management server; select SNMP version and read/write scope intentionally; limit management access to authorized hosts. | `show clock`; `show ntp associations`; `show logging`; `show snmp`; verify received events/queries in the Packet Tracer server service UI when modeled. | Packet Tracer models some services but a green service toggle alone is not proof of a successful exchange. Confirm feature and commands on the device. [Cisco NTP command reference](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/bsm/command/bsm-cr-book/bsm-cr-n1.html) · [Packet Tracer FAQ](https://prelogin-authoring.netacad.com/sites/default/files/cisco-packet-tracer-faq.pdf) |
| NAT/PAT | Mark inside/outside interfaces; decide static, dynamic, or overload/PAT; permit only intended inside sources and keep a working outside route. | `show ip nat translations`; `show ip nat statistics`; generate a client flow to a reachable outside test host, then inspect translations. | Translation state is created by traffic and may age out. It does not prove inbound reachability or firewall policy. [Cisco NAT monitoring](https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/ip-addressing/b-ip-addressing/m_iadnat-monmain-xe.html) |
| ACLs, SSH, basic device security | State direction and interface, order rules from specific to general, account for implicit deny, and allow required management/control traffic. Prefer SSH, authenticated local/AAA users, `enable secret`, and saved config; disable unused services/ports when the model supports it. | `show access-lists`; `show ip interface <port>`; `show ipv6 access-list`; `show ip ssh`; test allowed and denied sources separately; `show running-config` and `show startup-config`. | ACL order/direction can cut off management or routing. Secure configuration is not a substitute for credential handling or a production security review. [Cisco IPv6 ACL guide](https://www.cisco.com/c/en/us/td/docs/routers/ios-xe/security-vpn/security-vpn/m_ip6-acls-xe.html) · [Cisco SSH guide](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/sec_usr_ssh/configuration/xe-2/sec-usr-ssh-xe-2-book/sec-usr-ssh-sec-shell.html) |
| QoS: classification, marking, queuing | Define which traffic matters, how it is matched (for example, ACL or DSCP), where marking/trust occurs, and what queueing, priority, shaping, or policing policy is intended. Check the platform's queue model and interface speed first. | `show class-map`; `show policy-map`; `show policy-map interface <interface>`; generate representative traffic and inspect class counters/marks/drops. | Guidance only unless exact hardware/software supports the policy. QoS counters or Packet Tracer events do not establish real throughput, latency, or congestion behavior. [Cisco QoS classification](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/qos_classn/configuration/xe-16-12/qos-classn-xe-16-12-book/qos-classn-ntwk-trfc.html) · [Cisco QoS marking verification](https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/qos/b-quality-of-service/m_qos-mrkg.html) |
| Discovery, config backup, and model-driven management | Use CDP for Cisco-neighbor discovery and LLDP for multivendor discovery where policy allows. Choose a reviewed backup destination/retention policy. Use NETCONF/RESTCONF only when the exact device exposes the required YANG models, transport, and authorization. | `show cdp neighbors detail`; `show lldp neighbors detail`; `show running-config`; `show startup-config`; `show archive`; for supported IOS XE NETCONF: `show netconf-yang datastores`, `show netconf-yang sessions`. Check RESTCONF/API status with an authorized client and read-back of the intended resource. | Guidance only: discovery can be disabled or filtered; backup/archive commands and storage vary; NETCONF/RESTCONF support depends on platform, release, models, and access setup. Do not promise Packet Tracer automation or API support. [Cisco CDP](https://www.cisco.com/c/en/us/td/docs/switches/lan/c9000/lyr2-fwd/cdp-lldp-mac-udld/cdp-lldp-mac-udld-configuration-guide/c-configure-cdp.html) · [Cisco LLDP](https://www.cisco.com/c/en/us/td/docs/switches/lan/c9000/lyr2-fwd/cdp-lldp-mac-udld/cdp-lldp-mac-udld-configuration-guide/c-configure-lldp.html) · [Cisco configuration archive/rollback](https://www.cisco.com/c/en/us/td/docs/routers/ios-xe/system-management/system-management/m_cm-config-rollback-0.html) · [Cisco NETCONF](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/prog/configuration/1715/b_1715_programmability_cg/netconf_protocol.html) · [Cisco RESTCONF](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/prog/configuration/1715/b_1715_programmability_cg/m_1715_prog_restconf.html) |
| WAN serial, PPP, Frame Relay, GRE/VPN | Identify actual serial modules and DCE end; choose matching encapsulation/authentication; for Frame Relay map both sides' DLCIs/PVCs; for GRE/IPsec define both peers, underlay routes, tunnel addresses, selectors/keys and return routes. | `show ip interface brief`; `show controllers serial <port>`; `show interfaces serial <port>`; `show frame-relay pvc`; `show frame-relay map`; `show interfaces tunnel <n>`; VPN-specific SA/status command supported by the model. | Advanced VPN requires an explicit model and feature set. A tunnel interface up is not proof of working encrypted traffic. PT lists GRE/IPsec and WAN protocols as modeled features, with simplified IOS behavior. [Cisco GRE guide](https://www.cisco.com/c/en/us/td/docs/ios/12_4/interface/configuration/guide/inb_tun.html) · [Packet Tracer FAQ](https://prelogin-authoring.netacad.com/sites/default/files/cisco-packet-tracer-faq.pdf) |
| Wireless | Choose AP/router mode, band/channel, SSID, authentication/encryption, client radio/module, DHCP/gateway and any wired VLAN. Secure with WPA2/WPA3 where both selected devices support it; avoid treating WEP as secure. | AP/router association/client status; client `ipconfig`/`ipv6config`, `ping <gateway>`; check DHCP and server reachability after association. | Match exact wireless device/client radios and Packet Tracer version; modeled RF/security is not a real RF survey or production security assessment. [Packet Tracer FAQ](https://prelogin-authoring.netacad.com/sites/default/files/cisco-packet-tracer-faq.pdf) · [Packet Tracer server/end-device tools](https://tutorials.ptnetacad.net/help/default/config_servers.htm) |
| Troubleshooting | Move from physical/link → L2/VLAN → host addressing/gateway → routing/return path → ACL/NAT → application/DNS. Change one variable and retain before/after evidence. | `show interfaces`; `show vlan brief`; `show interfaces trunk`; `show ip interface brief`; `show ip route`; `ping`; `traceroute`; `arp -a`; `nslookup`; Simulation Mode events. | Wait for link/STP/ARP convergence and retry first ping. Read partial/error status; offline checks do not execute Packet Tracer pings. [Packet Tracer FAQ/troubleshooting](https://tutorials.ptnetacad.net/help/default/faqTroubleShoot.htm) |

## Reading and evidence boundary

Use Cisco configuration/command references for protocol semantics and CLI examples; use Packet Tracer help/FAQ for emulator-specific dialogs, modeled tools and limitations. The FAQ's modeled-protocol list is not a guarantee for every chassis or command. Record the Packet Tracer release and actual model/modules, inspect available commands, and distinguish address-plan arithmetic, saved-file integrity, offline modeling and a runtime test in the exact file. [Packet Tracer FAQ](https://prelogin-authoring.netacad.com/sites/default/files/cisco-packet-tracer-faq.pdf) · [Cisco IOS XE configuration guides](https://www.cisco.com/c/en/us/support/ios-nx-os-software/ios-xe-26/products-installation-and-configuration-guides-list.html)
